# Waveshare RLCD 额度页与局域网后台设计

## 目标与边界

本功能只为 `waveshare-s3-rlcd-4.2` 构建启用，在现有天气、音乐、番茄钟页面之外加入“额度”页面，并提供局域网后台管理页面。第一版最多配置 32 个额度项，支持多个同类型账号；设备不会向公网暴露管理端口，也不会把密钥回传到浏览器。

内置数据源参考 CC Switch 当前实现：

- Codex：`GET https://chatgpt.com/backend-api/wham/usage`，Bearer access token，可附带 `ChatGPT-Account-Id`。
- Kimi Coding：`GET https://api.kimi.com/coding/v1/usages`，Bearer API key。
- 智谱 GLM：中国站或国际站的 `/api/monitor/usage/quota/limit`，Authorization 直接使用 API key。
- DeepSeek：`GET https://api.deepseek.com/user/balance`，Bearer API key。
- 通用 JSON：为未来或自建聚合服务保留，可配置 URL、Bearer 凭据及简单字段名。
- 手动项：无网络请求，由后台直接填写百分比、余额与重置时间。

上述供应商接口（尤其 Codex ChatGPT 后端接口）不是稳定的统一标准；适配器应把 HTTP 状态、认证失效、解析失败分别记录，并允许以后独立升级。

## 屏幕设计

额度页沿用 400×300 单色 RLCD 的硬朗卡片语言：

```text
┌────────────────────────────────────────┐
│ QUOTA  1/3                   更新 14:35 │
├───────────────────┬────────────────────┤
│ 工作 Codex      ! │ 个人 GLM            │
│ 5H  ███████░ 72% │ 5H  ███░░░░░ 31%   │
│ 7D  █████░░░ 54% │ 周   ██████░░ 65%  │
├───────────────────┼────────────────────┤
│ Kimi 主号          │ DeepSeek ¥82.40     │
│ 5H  ██░░░░░░ 20% │ 可用余额            │
│ 周   ████░░░░ 43% │ 已刷新              │
└───────────────────┴────────────────────┘
```

- 每屏 4 个卡片，额度页停留时每 10 秒自动翻到下一子页。
- USER 单击仍按管理员配置的顶层顺序切页；额度内部子页也作为连续页面参与循环，不改变原来的长按“系统信息”。
- 右上角显示“最近一次全部启用项均刷新成功”的时间。部分失败时保留原时间并显示 `!`。
- 瞬时网络错误保留最后成功值并标记陈旧；认证或解析错误同样保留最后值，但后台显示明确错误。
- 没有配置额度项时显示设备后台地址和添加提示。

## 页面与数据模型

页面配置包含 `weather`、`music`、`pomodoro`、`quota` 四个固定页面 ID，每项有 `enabled` 和 `order`。至少保留一个页面启用；额度页面自身只有一个顶层位置，内部页数按启用额度项动态计算。

额度配置项字段：

- `id`、`enabled`、`order`、`name`
- `provider`：`codex`、`kimi`、`glm-cn`、`glm-global`、`deepseek`、`generic-json`、`manual`
- `base_url`（可选）
- `secret`（只写）、`account_id`（Codex 可选）
- 通用/手动源的 `total`、`remaining`、`unit` 与字段名

运行结果包含最多两个主层级：层级名、已用百分比、余额/总额、单位、重置时间；另含刷新时间、是否陈旧和短错误码。屏幕只读快照，网络任务与 LVGL 不相互持锁。

## 刷新与资源控制

- 后台任务启动后等待 Wi-Fi，并在设备连续空闲 5 秒后执行。
- 开机首次刷新，之后每 5 分钟刷新一次；后台可触发立即刷新。
- 每次只发送一个 HTTPS 请求，单请求超时 10 秒，避免占用语音链路和内部 RAM。
- 设备正在连接、聆听或播放语音时暂停新请求。
- 响应体限制为 16KB，超过限制直接失败；令牌和响应体绝不写入日志。
- 更新配置后立即保存并触发刷新。最后成功结果另存缓存，重启后仍可显示陈旧值。

## 局域网管理后台

地址为 `http://<设备IP>:8080/admin`；首次访问设置管理员密码，之后用户名固定为 `admin`。后台为固件内嵌的单页 HTML/CSS/JS，不依赖 CDN：顶部显示设备 IP、刷新状态和手动刷新按钮；左侧调整页面启用与顺序；主体管理动态额度卡片。

安全约束：

- 密码采用随机盐加 SHA-256 摘要保存，不保存明文。
- 登录签发随机内存会话，使用 `HttpOnly; SameSite=Strict` Cookie，30 分钟无操作失效。
- 所有修改请求校验会话及同源 CSRF token。
- API 读取配置只返回 `has_secret`，不返回已有密钥；留空表示保留，明确勾选才清除。
- 限制请求体大小、条目数与字符串长度，不支持上传或执行脚本。
- HTTP 明文本身不能抵御同一局域网内的抓包，因此后台只监听设备 LAN/AP 接口，不做端口映射；高安全环境应使用单独 VLAN 或由 HTTPS 聚合服务代取上游凭据。

API：`/api/setup`、`/api/login`、`/api/logout`、`/api/status`、`/api/pages`、`/api/quotas`、`/api/refresh`。

## 持久化与升级

原始 `nvs` 分区仅 16KB且还承载 Wi-Fi 等系统设置。板级分区表把 `assets` 从 6MB 缩为 5.75MB，在末尾新增 256KB `quota_nvs`；应用槽、OTA 数据和原 NVS 地址均不变。额度项逐条存储，避免 NVS 单值长度限制。分区保存 schema 版本，以便以后迁移。

验收标准：

1. 未配置、单项、4 项、5 项及 32 项时页面均不越界并正确分页。
2. 多个同供应商账号可以独立保存、刷新和显示。
3. 五分钟自动刷新、十秒翻页、右上刷新时间及失败陈旧标记符合设计。
4. 首次设置、登录超时、错误密码、秘密只写、页面排序和重启持久化通过。
5. 编译后应用和资源均未超过分区，整包烧录并通过串口启动检查。
